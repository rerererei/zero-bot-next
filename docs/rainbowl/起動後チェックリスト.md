# Bot起動後チェックリスト：入場〜面談合否判定フロー

> 実装済みコードを本番サーバーで動作確認する際の手順メモ。
> 実機未検証の実装のため、ここに書いた順番で1つずつ確認すること。

---

## 0. 前提

- AWSインフラ（`zero_bot_rainbowl_applicants`テーブル、`zero_bot_guild_config`の`rainbowl`設定）は投入済み（[scripts/rainbowl/setup_infra.py](../../scripts/rainbowl/setup_infra.py)実行済み）
- Botのコンソール出力（ログ）を見られる状態にしておく。エラーはすべて`[rainbowl]`プレフィックス付きで出力される

---

## 1. 起動直後・1回だけ行う作業

- [ ] Botを起動し、コンソールに以下が出ることを確認
  - `✅ Cog loaded: cogs.rainbowl_onboarding`
  - `✅ Cog loaded: cogs.rainbowl_interview`
  - `✅ スラッシュコマンド同期完了`
- [ ] Discord側で `/rainbowl_setup_buttons` を**1回だけ**実行する（運営権限が必要）
  - 入会案内チャンネル1〜6に「次へ」ボタン、7（入会申請）に「入会申請」ボタンが1つずつ投稿されることを確認
  - ⚠️ **べき等ではない**。誤って複数回実行するとボタンが重複投稿される（重複した場合は手動でメッセージを削除する）
- [ ] 「受付」カスタム絵文字 `<:uketsuke:1535212269472849971>` がこのサーバーに実在するか確認（存在しないとリアクション設置が失敗する）

---

## 2. 入場〜入会案内（段階開放）

テスト用アカウントで確認する（本番アカウントで試す場合は結果的にロール・チャンネルが実際に動く点に注意）。

- [ ] テストアカウントがサーバーへ入場（既に参加済みの場合は一度退出してから再参加）
  - [ ] 「入場者詳細」チャンネルにEmbedが投稿される
    - 表示名／@handle／数値ID／アイコン／アカウント作成日・年数／入場回数が正しく表示される
    - bio欄：取得できるか、「取得不可」になるか確認（**未検証の実験的機能**）
    - 初回入場なら「初回入場」、再入場なら「前回どこまで進んだか」「前回の合否・理由」が表示される
  - [ ] 「入場者」ロールが付与される
  - [ ] 「# ようこそ」だけが見え、他の入会案内チャンネルは見えない
- [ ] 「# ようこそ」の「次へ」を押す
  - [ ] 本人だけに「30秒でわかる概要」が見えるようになる（他の入場者には影響なし）
  - [ ] 応答メッセージ（Ephemeral）が返る
- [ ] 同様に2〜6チャンネルすべてで「次へ」を押し、1つずつ開放されることを確認
  - [ ] 古いボタン・二重押下を試し、無視される（Ephemeralで「使用できません」等が返る）ことを確認

---

## 3. 入会申請〜プロフィール提出

- [ ] 「# 入会申請」の「入会申請」ボタンを押す
  - [ ] ロールが「入場者」→「申請中」に変わる
  - [ ] 面談・手続きカテゴリーに本人専用チャンネルが生成される
    - チャンネル名が `{表示名}さん（{DiscordID}）` の想定通りの見た目になっているか確認（**Discordの自動変換・除去の実挙動は未検証**）
    - 閲覧権限が本人＋運営のみになっているか確認
  - [ ] チャンネルに案内文・プロフィールテンプレートが2通に分けて投稿される
  - [ ] 入会案内チャンネル2〜7に残っていた個別オーバーライドが削除されている
  - [ ] 同じボタンをもう一度押しても二重申請にならない（Ephemeralで「既に申請済みです」等）
- [ ] 本人専用チャンネルへテンプレートをコピーして記入・送信
  - [ ] その投稿に「受付」スタンプが自動で付く
  - [ ] 続けて別のメッセージを送っても、そちらにはスタンプが付かない（最初の投稿だけが対象）

---

## 4. 承認・転記

- [ ] 運営ロールを持つアカウントで、プロフィール投稿に同じ「受付」スタンプを押す
  - [ ] 「応募者プロフ置き場」へ `@本人メンション + プロフィール全文` の形式で転記される
  - [ ] 本人がスタンプを押しても転記されない（本人操作は無効）ことを確認
  - [ ] 複数の運営が続けてスタンプを押しても、転記は1回だけ

---

## 5. 合否判定

### 5-1. 合格（`/ok`）

- [ ] 本人専用チャンネル内で運営が `/ok` を実行
  - [ ] コメント入力モーダルが表示される（未入力でも送信可）
  - [ ] 送信後：
    - [ ] ロールが「申請中」→「合格」に変わる
    - [ ] 「合格通知」チャンネルへ合格メッセージが投稿される
    - [ ] 「合否記録」チャンネルへ緑の左線Embed（ユーザー名・ID・アイコン・コメント）が投稿される
    - [ ] 本人専用チャンネルが即座に削除される

### 5-2. 不合格（`/ng`）

別のテストアカウントで確認（`/ok`で使ったアカウントは合格済みのため退会・再入場が必要）。

- [ ] 本人専用チャンネル内で運営が `/ng` を実行
  - [ ] 理由入力モーダルが表示される（未入力だと送信できない）
  - [ ] 送信後：
    - [ ] 対象ユーザーが**無連絡のまま**キックされる
    - [ ] 「合否記録」チャンネルへ赤の左線Embed（ユーザー名・ID・アイコン・理由）が投稿される
    - [ ] 本人専用チャンネルが即座に削除される
- [ ] 運営権限を持たないアカウントで `/ok` `/ng` を実行し、拒否されることを確認
- [ ] 無関係のチャンネル（本人専用チャンネル以外）で `/ok` `/ng` を実行し、拒否されることを確認

---

## 6. 再入場（履歴）

- [ ] 5-2でキックしたアカウントを再度サーバーへ招待・入場させる
  - [ ] 「入場者詳細」Embedの「入場回数」が2回目になっている
  - [ ] 「前回どこまで進んだか」が `REJECTED`（不合格）、「前回の合否・理由」に5-2で入力した理由が表示される

---

## 7. 既知の未実装・未検証事項（このテストの範囲外）

- プロフィール未提出3日後の自動キック（日次バッチ）は**未実装**
- bio取得は実験的実装（動かなくても仕様通り、フォールバック表示になる）
- 表示名がチャンネル名制約に引っかかる場合の見た目は未対策（気になる見え方があれば記録しておく）
- 合格後の本人専用チャンネルは削除タイミングを検討中だったが、実装は即時削除で確定済み（このチェックリストの5-1で確認）

---

## 8. 何か失敗したら

- コンソールログの `[rainbowl]` プレフィックス付きメッセージを確認する
- DynamoDBの実際の値を確認したい場合：
  ```
  aws dynamodb get-item --table-name zero_bot_rainbowl_applicants --key "{\"guild_id\":{\"S\":\"1533518300271607929\"},\"user_id\":{\"S\":\"<対象のDiscordユーザーID>\"}}" --region ap-northeast-1
  ```
